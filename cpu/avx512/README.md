# Bare-Metal Intel AVX-512 VNNI L3-Resident `HoloSphere-V3 15M` CPU Engine (`Track S125` / `EXP-Q30b`)

Zero-dependency C11 + Intel AVX-512 (`VPDPBUSD`, `VPOPCNTQ`, `VPERMT2D`) inference engine implementing the full `HoloSphere-V3 15M` architecture (`D=512, H=16, head_dim=32, L=6, d_ff=800, V=256` tied `FWHT_256 x bent4` `0 B` LM head + `ByteConv4` + `V_ring` + SFU-free `CayleySU2` + `S_fast` Woodbury + `SwiGLU`) strictly inside the `24 MiB` L3 cache of an Intel Core `i9-11900H`. **All weights benchmarked and traced here are deterministic `SplitMix64` synthetic weights (`seed=125001`), not trained checkpoint weights.**

## 1. Key Design & Honesty Scope

- **L3-Resident Arena (`9.010 MiB` = `37.541%` of `24 MiB` L3) & Off-Arena Scratch Accounting:** The `mmap` arena holds `8,837,120 B` (`8.428 MiB`) synthetic weights + `610,304 B` (`0.582 MiB`) $O(1)$ persistent recurrent state (`0 B/tok` KV growth) = **`9,447,424 B` (`9.010 MiB`)**, strictly under the `< 12 MiB` gate (`PREREG-W14` `SHA-256 = 871900e5d6c860ac159f43ca6b4767e7c128d0b4f7748edf788d56e9cb535d3e`). Internally, `holo_engine_init` rounds the committed `memset` length up to `2 MiB` (`10,485,760 B` = `10.000 MiB`) inside a `12,582,912 B` (`12.000 MiB`) virtual `mmap` reservation to guarantee `2 MiB` alignment. Outside the `mmap` arena, `main()` allocates `sizeof(HoloV3Engine) = 35,088 B` (`34.27 KiB`) on the stack — including `33,900 B` (`33.11 KiB`) of activation/logit/quantized-`H_4` scratch buffers (`x_buf..logits_buf` = `32,896 B`, `QuantActH4 qact` = `1,004 B`) — plus `sizeof(GemvPool) = 392 B` and `< 2 KiB` of per-step function-local stack arrays (`1,024 B` in `step_tied_fwht256_lm_head`, `512 B` in `step_cayley_sfast`, `256 B` in `step_vring_and_mix`, `128 B` in `quantize_act_h4`), for a total active working set of `~9.044 MiB` (`~9,484 KiB`).
- **Bit-Exact `A_16 Block-H4` `VPDPBUSD` Equivalence:** Pre-applying symmetric orthogonal `H_4` once to activation `x` and quantizing per 32-element group to signed `int8` (`xq in [-127, +127]`) enables bias-shifting signed `int4` nibbles `c in [-8, +7]` to unsigned `u = c + 8 in [0, 15]` via one `vpxorq(..., 0x88)` and accumulating `64` exact `u8 * s8` MACs per `_mm512_dpbusd_epi32` (`vpdpbusd`), subtracting `8 * sum(xq[g32])` for bit-exact `0.0`-ULP parity between scalar C11 and AVX-512 VNNI across `1T`, `4T`, and `8T`.
- **`[16, 11, 4]` Nibble-LSB Bit-Plane SECDED Scope (Razor Parity):** Inline `_mm512_popcnt_epi64` (`vpopcntq`) verifies the `[16, 11, 4]` Extended Hamming syndrome over the **`16`-bit packed nibble-LSB control plane** (`w64 & 0x1111111111111111ULL`, i.e., `1/4` of payload bits, matching `holosphere#3` & `silikernels#4` Razor bit-plane canary semantics). Live self-test certifies `16/16` single-bit LSB bit-exact repair and `120/120` double-bit LSB detection; nibble upper bits `1..3` (`3/4` of weight payload bits) are unguarded payload bits.
- **External FP64 Oracle & Toolchain-Specific `objdump` Scope:** The standalone FP64 reference oracle used to record `fp64_oracle_max_abs_logit_diff` / `fp64_oracle_max_abs_hidden_diff` in `receipts/s125_avx512_l3_benchmark_results.json` is external and not bundled in this repository; in-tree verification reproduces the deterministic C11 trace digests (`logits=6fc017bea5754bb1`, `hidden=3a65e5960be737a7`, `greedy_tokens=[149,239,169,143,89,215,50,229]`) and verifies the pinned receipt fields rather than recomputing the FP64 oracle. Likewise, the `objdump -d` instruction counts (`vpdpbusd=4`, `vpopcntq=10`, `vpermt2d=7`) are illustrative and specific to `gcc (GCC) 16.2.1 20260810` (`-O3 -march=native`) on the measured `i9-11900H` host rather than compiler-invariant.
- **Uncontrolled RAPL Stdout Hook:** In `--mode bench`, `holosphere_v3_avx512.c` prints an optional `rapl_mj_per_tok` diagnostic read from `/sys/class/powercap/intel-rapl:0/energy_uj` (or `-1.0` when unavailable). Any energy value printed by that hook is uncontrolled laptop telemetry, is not certified as controlled power measurement, and is excluded from public copy.
- **Hardened Strict CLI:** Validates every integer flag via `endptr`/`errno`/sign-checked strict parsing (`--threads 1..16` emitting sanitized `pool.n_threads`, `--tokens >= 1`, `--warmup >= 0`, `--hugepages 0|1`, unsigned `--seed`), validates `--mode` (`bench|trace`) and `--backend` (`avx512|scalar`), checks `pthread_create` return codes with clean worker teardown, and returns exit code `5` on non-zero runtime syndrome faults in both `trace` and `bench` modes.
